关于我

一个喜欢把问题拆开看的学生

我是高旭辰，杭州市文海中学九年级学生。在校担任少先队文娱委员、学生会播音主持组组长， 曾任校“鲲鹏”辩论社社长。

让我着迷的是“为什么”。为了搞清楚钱塘江古海塘凭什么能扛住潮水，我们六个人跑到江边， 照着土塘、柴塘、石塘三种古法各搭了一座模型，用水泵冲了整整一个上午，最后量出结论： 抗长期高速冲击，石塘 > 柴塘 > 土塘。

另一条线是“怎么讲清楚”。我写过英文讲稿 Generative AI: From Models to Agents， 从图灵之问讲到 Transformer，再讲到 Agent 比聊天机器人多做的那三件事； 也在校园航天科普展上策划过“深空展望”展位。科创比赛里的答辩材料基本都是我自己筹备的—— 把一个项目讲清楚，和把它做出来一样重要。

再往后是“做出来”。校园里每天都有人丢东西——丢的人不知道去哪儿找，捡到的人交到德育处也 常常对不上号。我把这件事做成了一套系统：服务端放在德育处，班级端装在教室的电脑上， 两边录入的记录会自动互相匹配、互相提醒，后来又接入了大模型来做物品识别与语义匹配。

这两年拿过全国青少年人工智能大赛国家二等奖、UNESCO“智玩 AI”青少年 AI 与媒介素养案例征集活动 中国区二等奖、“礼仕杯·问浙苍穹”全国青少年航天创新大赛杭州市一等奖； 也入选中科院基础疾病与肿瘤研究所“未来科学家”夏令营，持有 EY 与 Microsoft 联合颁发的 A.I. Skills Passport。

软件系统 2025 — 2026

校园失物招领系统 CLFS

丢的人和捡到的人之间，原本只隔着一句“你去德育处问问”。这套系统把这条链路真正接通： 服务端部署在德育处，班级客户端按班安装，启动后会自动发现局域网内的服务端地址并连上， 两端通过长轮询实现实时通知——一旦出现匹配，对方班级的客户端会立刻弹出提醒。

服务端用 Flask 提供一整套 REST API，数据落在 SQLite 上；客户端是 Tkinter 桌面程序， 另有单文件的移动端网页版本。服务端与班级客户端合计约 7,700 行代码，两端共用同一份核心模块， 匹配算法与业务规则不会因为各写一遍而跑偏。

匹配是核心。新记录入库时，会在近 90 天的对端记录里按“物品名 0.5 + 地点 0.2 + 时间 0.15 + 描述 0.15”计算加权相似度，超过阈值就推送给对方班级。为了让“水壶”和“保温杯”这类字面不同、 意思相近的记录也能对上，我在算法之上又接了一层大模型：拍照可自动识别物品并填充表单， 语义向量负责补足编辑距离的盲区，还做了自然语言搜索与通知文案润色。

我的角色

独立完成：系统设计、服务端与班级客户端开发、移动端网页，以及大模型接入模块。

  • C/S 架构
  • Flask · REST API
  • SQLite
  • Tkinter
  • 多模态识别
  • 语义匹配
  • 实时推送
  • PyInstaller 打包

科学实验 2024.08

海塘建模：三类古海塘抗水流冲击实验

以钱塘江古海塘为对象，按土塘、柴塘、石塘三种古法结构搭建模型，用水泵模拟低速、中速、高速水流冲击， 记录不同条件下的损毁状态，对比三类结构长期抗冲能力的差异。

为了让水流“可测量”，我们用自由落体公式反推水泵三档的实际流速（约 4.5 / 6.7 / 11.1 m·s⁻¹）， 把定性的“冲得动冲不动”变成了可比较的数据。

我的角色

负责中速、高速两级冲击实验的操作与数据记录；独立完成项目成果的演示文稿与视频制作。

  • 自由落体测速
  • 控制变量法
  • 模型搭建
  • 数据对比分析

结论抗长期高速水流冲击能力：石塘 > 柴塘 > 土塘
